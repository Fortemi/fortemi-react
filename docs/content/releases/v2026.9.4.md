# fortemi-react v2026.9.4

This release integrates native PGlite restore for `2.0.0/full-v1`. Imported
records become available through native repositories, search and relationship
reads. Subsequent current-state exports reflect ordinary native edits instead
of silently selecting an earlier archival snapshot.

## Packages

- `@fortemi/core@2026.9.4`
- `@fortemi/graph@2026.9.4`
- `@fortemi/react@2026.9.4`

## Restore and export

The public importer applies all 33 declared components transactionally after
validation. Replacement follows selected ownership and preserves unrelated
records and retained references. Native history, SKOS, provenance, embeddings,
graph/community records and mandatory attachment bytes remain profile-scoped.
Incompatible native representations produce typed losses rather than a success
claim that silently discards required state.

Explicit archival APIs retain their separate logical-file and signature
preservation guarantee. Native exports regenerate manifest metadata and checksums;
they do not reuse a signature over different bytes. The default standalone export
uses reported `core-v1`, and ambiguous or unsupported scope requests fail clearly.

## Remote adapters

Note, link, SKOS and provenance reads validate pinned producer envelopes and UTC
timestamps. Search and lifecycle intents use supported server operations, while
authorization, transport and malformed-response failures stay typed and bounded.
These changes do not establish successful vector retrieval or authenticated
operation on every remote deployment.

## Verification boundary

The implementation has native clean/mixed/repeated import, conflict, rollback,
post-import CRUD and clean-installed-package regression coverage. Release gates
must pass on the final release source, and publication must be verified against
actual package and mirror bytes before release completion is claimed.

Fortemi remains the shard schema/profile authority. Historical fixtures and their
receipts are unchanged; current implementation receipts bind current source.
Producer corrections are tracked in Fortemi #1147, coordinated with React #424.
Exact released producer/consumer and platform qualification remains separate.
The suite audit remains **NO-GO** for unqualified parity, complete backup or
portability. RecordStore is still limited to its named `record-v1` subset.
