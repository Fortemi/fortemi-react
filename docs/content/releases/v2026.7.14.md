# fortemi-react v2026.7.14

fortemi-react v2026.7.14 publishes the current receipt-backed Knowledge Shard
implementation and the AIWG `core-v1` lifecycle and hierarchy projection.

## Highlights

- **Receipt-backed matrix cells (#354, #355, #382):** current PGlite,
  RecordStore, and Fortemi fixtures bind clean destinations, repeated imports,
  semantic re-export, profile semantics, version skew, malformed input,
  resource limits, and zero mutation on rejection. Historical generators pin
  the producer version named by their receipt so later releases reproduce
  identical evidence bytes.
- **AIWG lifecycle semantics (#393):** the converter pins AIWG authority commit
  `dbbfee78993365686f3c8283f93ba8ef7172e7d4`. Source directories become stable
  native `core-v1` collection hierarchies, while only explicit
  `state_transfer.deleted_at` becomes a tombstone. Operational issue/workflow
  state remains separate metadata.
- **Deterministic clean PGlite projection:** repeated import preserves native
  collection parents, direct note counts, explicit tombstones, and the complete
  embedded AIWG source record through semantic re-export.
- **Restored project Git bootstrap (#394, #396):** commit signing and Gitea
  pushes use the least-privilege project runtime AppRole from encrypted systemd
  credentials and keep decrypted material on tmpfs. The release key remains a
  separate tag-only authority.

## Compatibility

The published package continues to select Knowledge Shard semantics by the
exact `(manifest.version, manifest.profile)` tuple. Schema `1.2.0/core-v1`,
schema `1.2.0/record-v1`, and the receipt-backed schema `2.0.0/full-v1`
boundaries remain distinct.

AIWG conversion remains an explicit bridge from the static AIWG v2 export
contract into a Knowledge Shard. It is not a shared schema with AIWG's static
index or Fortemi's live persistence plane.

## Claim Scope

This release proves the React implementation and its existing immutable
receipts. It does not alone prove the two AIWG producer-to-PGlite/Fortemi
`core-v1` matrix cells. Those claims require a canonical fixture generated
through this released package plus committed producer and clean-destination
consumer receipts.

No unqualified full-portability, complete-backup, or suite-parity claim follows
from this release.
