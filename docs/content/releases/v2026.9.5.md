# fortemi-react v2026.9.5

## Packages

- `@fortemi/core@2026.9.5`
- `@fortemi/graph@2026.9.5`
- `@fortemi/react@2026.9.5`

All three packages remain in version lockstep. Graph and React carry the
coordinated package version; capability-validation behavior changes are in Core.

## Capability Validation

The public unknown-JSON boundary validates capability descriptors and requests
before negotiation. Unknown states, malformed or unsupported versions, unsafe
numeric components and prerelease-versus-stable mismatches fail closed with
typed diagnostics. Already prevalidated callers were not affected by the former
unknown-state bypass. Shared authority vectors run through installed public ESM
exports; they do not establish live remote execution maturity.

Producer-owned HTTP read, negative-response and mutation fixtures are pinned
with source/digest receipts. Current tests replay those captured bytes. Personal
required-key receipts do not qualify hosted tenant/role authorization, and
fallback evidence does not prove successful semantic retrieval.

## Release Reliability

Publishers preserve existing assets, reject conflicting bytes and verify actual
registry and release attachment digests. Packed workspace dependency ordering
is normalized to make independently produced artifacts comparable.

Core CI uses three serial, two-worker partitions with normal file isolation.
Four disposable fixed-path worktrees keep producer and merger identity stable.
The merger validates source/runtime/root, raw artifact hashes and exhaustive
file/case inventory before native coverage aggregation; the global statement
coverage floor remains 79 percent. Native multi-restore tests retain their
assertions with explicit bounded budgets.
