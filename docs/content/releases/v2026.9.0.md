# fortemi-react v2026.9.0

fortemi-react v2026.9.0 is the September 2026 release for evidence-bearing
dataset workflows, configured inference routing, and provenance-centered React
examples.

## Highlights

- **Negotiated dataset execution:** `@fortemi/core` publishes versioned runtime
  descriptors and pure capability negotiation. Required mismatches fail before
  execution; optional mismatches identify the selected fallback and changed
  guarantees.
- **Resumable ingest and lineage:** processing plans bind source,
  configuration, destination, rejection, and reconciliation policy. Atomic
  receipts, scoped idempotency, validated checkpoints, and an append-only
  evidence ledger provide deterministic reference semantics for adapters.
- **Materialization profiles:** eight composable profiles cover canonical
  storage, lexical/vector/hybrid indexes, embeddings, graph retrieval, and
  community materialization. Receipts identify the actual profile, backend,
  source/configuration digests, freshness, privacy decisions, degradation, and
  measurements.
- **React dataset workflow:** the `@fortemi/react/dataset` subpath provides a
  headless workflow machine, hook, accessible components, and fixtures for
  connection checks, bounded previews, plan approval, runs, redacted
  rejections, status, and bounded lineage traversal.

- **One configured provider runtime:** deployments can register browser
  OpenAI-compatible providers, host-bridge services, and discovered local
  endpoints through the same runtime configuration. Only configured providers
  are available, and existing single-provider setups continue to work.
- **Task-aware routing:** provider chains can differ for query embeddings,
  document embeddings, large-document embeddings, general chat, revision, and
  tagging. Routes support capability and profile requirements, ordered
  fallback, validation, previews, probes, and observable route events.
- **React route controls:** `FortemiProvider` exposes the configured registry,
  and `useInferenceRouting` lets React surfaces inspect routes, validate them,
  preview selection, and probe configured providers.
- **Visible W3C PROV metadata:** `useNoteProvenance` reads stored
  `provenance_edge` rows alongside creation, job, and revision history. The
  research-workbench demo seeds source entities and citation derivations and
  renders their activities, agents, and `prov:wasDerivedFrom` values.

## Compatibility

The dataset capability, ingest, lineage, and materialization contracts are new
v1 surfaces. Their bundled in-memory implementations and fixtures are reference
semantics, not proof of live remote persistence maturity. Runtime capability
claims require implementation-specific evidence; required capabilities fail
closed before execution.

The React dataset workflow delegates I/O and execution to a
`DatasetWorkflowApi`. It does not create another ingest, lineage, or persistence
authority. Sensitive connector fields are write-only in the provided form
controls.

Inference routing is additive. A deployment may keep one default provider or
configure task-specific chains; explicit provider selections remain bounded to
their requested chain. Streaming binds to one selected provider for the life
of the stream rather than switching mid-response.

Stored provenance rows use the existing live PGlite provenance table. The
React timeline and EX-18 presentation do not introduce a new interchange
schema or merge provenance with the AIWG static-index contract.

## Claim Scope

This release does not change Fortemi #1081's suite-level `NO-GO` audit. The
AIWG static index, Knowledge Shard state transfer, and live Fortemi persistence
remain separate planes. Knowledge Shard claims still require a named
`core-v1`, `record-v1`, or `full-v1` profile and its executable receipt matrix.
