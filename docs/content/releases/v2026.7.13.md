# fortemi-react v2026.7.13

fortemi-react v2026.7.13 publishes the schema `2.0.0` presence-semantics,
PGlite `full-v1`, and native AIWG `full-v1` implementation boundary.

## Highlights

- **Lossless presence semantics (#379):** schema validation, PGlite,
  MemoryRecordStore, IndexedDB, AIWG conversion, import, export, and re-export
  preserve distinct absent, explicit `null`, empty, and value states. The
  generated authority matrix covers all 220 inventoried fields and six
  semantic states.
- **Complete PGlite `full-v1` (#380):** PGlite produces and persists all 33
  authority component families, stable identities and timestamps, attachment
  bytes and digests, signatures, tombstones, embeddings, SKOS, provenance,
  graph, and community data.
- **Native AIWG `full-v1` (#381):**
  `@fortemi/core/aiwg-index-shard` converts current AIWG v2 records into native
  typed schema `2.0.0/full-v1` components with deterministic checksums and
  explicit machine-readable losses.
- **Fail-closed mutation boundary:** unsupported presence states, invalid
  archives, missing required sidecars, and non-representable production state
  are rejected before database or blob mutation.

## Compatibility

Schema `1.x` `core-v1` and `record-v1` behavior remains available and covered
by regression receipts. Schema `2.0.0` semantics are selected by the exact
`(manifest.version, manifest.profile)` tuple; profile names alone do not imply
schema-2 behavior.

The archive-only AIWG conversion API rejects rich conversion when doing so
would discard required loss evidence. Consumers producing `full-v1` should use
the report-returning API and inspect its machine-readable losses.

## Claim Scope

This release proves the React producer and browser-persistence boundary. It
does not by itself prove unqualified full portability, complete backup, or
Fortemi server parity. Cross-repository capability advertisement remains gated
by React #382 and Fortemi #1084/#1087.
