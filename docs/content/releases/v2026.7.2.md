# fortemi-react v2026.7.2

fortemi-react v2026.7.2 brings the browser edition's binary-attachment handling
into parity with the Fortemi server contract, and adds a headless embedding path
so CLI and Node consumers can build embedding sets without a browser.

## Highlights

- **Binary attachment extraction (#227):** attachment rows carry `mime_type` and
  `extracted_text` (migration `0010`). Binary attachments are represented in the
  search, index, export, and embedding-set surfaces via extracted text plus a
  content-addressed attachment reference — never raw binary bytes. Raw bytes stay
  in `BlobStore`.
- **Extracted text everywhere it matters (#227):** extracted attachment text
  feeds live search, the static shard-reader search, embedding generation,
  virtual embedding-set query criteria, and concept tagging, so a note's attached
  documents are findable by their contents.
- **Headless embedding sets (#228):** the new `buildAiwgStaticEmbeddingSet`
  entrypoint generates `aiwg.fortemi.embedding.set.v1` sidecars from any Node-safe
  model backend, with no DOM or WebGL dependency. This unblocks CLI index building
  such as AIWG's `index embed`.
- **Shard parity:** notes carry server-compatible `attachments` in the Knowledge
  Shard export, so attachment metadata and extracted text travel with the note
  while raw bytes do not. Legacy React shards that used `binary_sources` remain
  importable.
- **Documentation:** backfilled the 2026-03 → 2026-05 monthly reports; enabled
  Pagenary HTML fallback and the open SEO profile; documented the attachment
  extraction contract and the CLI embedding-set path.
- **Release metadata:** package versions, runtime constants, API docs, and the
  release index were refreshed for `2026.7.2`.

## Compatibility

This is an additive release. The new attachment columns are additive browser-side
metadata (migration `0010` applies on open); server columns are unchanged, so
JSON format parity is preserved — notes export attachment projections via the
server `attachments` field, not raw attachment columns or blob payloads. Existing
Knowledge Shards that used the earlier React `binary_sources` field, embedding
sets, and static indexes remain valid. The headless embedding entrypoint adds no
model runtime dependency to `@fortemi/core`.
