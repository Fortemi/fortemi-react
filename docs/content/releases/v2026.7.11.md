# fortemi-react v2026.7.11

fortemi-react v2026.7.11 completes RecordStore collection hierarchy transport
and makes Knowledge Shard archive bytes reproducible. It is a full release of
the existing contract revision 19 and schema 1.2.0 profile boundaries.

## Highlights

- **RecordStore hierarchy parity (#355):** canonical collections preserve
  `parent_id` through memory storage, additive IndexedDB migration,
  `record-v1` import/export, and PGlite projection.
- **Atomic hierarchy validation:** missing collection parents and cycles are
  rejected before projection mutates PGlite or RecordStore state.
- **Reproducible shard bytes:** tar entries and the outer gzip header use
  canonical zero mtimes. Identical inputs now produce byte-identical archives
  across wall-clock times, enabling stable cross-repository receipt hashes.

## Compatibility

Contract revision 19 and Knowledge Shard schema 1.2.0 are unchanged. PGlite
continues to advertise `core-v1`, RecordStore continues to advertise
`record-v1`, and neither backend advertises `full-v1` production or
persistence. The deterministic archive change affects container metadata only;
manifest and component semantics remain unchanged.
